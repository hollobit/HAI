방법론

이 대시보드가 숫자와 문장을 어떻게 얻고, 어떻게 검증하며, 전망을 어떤 기준으로 그리는지에 대한 공개 문서.

1. 데이터 소스

  • 수치 (Metric) — Stanford HAI가 공식 공개한 CSV (aiindex.stanford.edu)에서 직접 가져옵니다. 파이프라인이 변형하지 않고 그대로 구조화된 JSON으로 저장합니다.
  • 서사 (Narrative + Quote) — 보고서 PDF 원문에서 LLM(Claude Sonnet 4.6)이 요약과 한국어 해설을 생성하되, 영어 인용은 원문 그대로 유지하고 사후 grep 검증을 통과해야만 저장됩니다.

2. 환각 방어 — 3중 장치

  1. 프롬프트 규칙: 인용은 변형 금지, 숫자는 인용 아닌 Metric에만 존재.
  2. 페이지 마커 주입: PDF 추출 단계에서 각 페이지 끝에 [p.NNN] 마커를 심어 LLM이 임의의 페이지 번호를 생성할 수 없게 만듭니다.
  3. Grep 검증: 저장 직전 모든 Quote.text_en이 원본 마크다운에 실제 등장하는지 확인. 실패 시 빌드 차단.

3. 전망 계산

선형·로그선형 회귀 2가지를 모두 적합하고 R²가 높은 쪽을 선택합니다. 신뢰구간은 잔차 기반 ±1.96σ.

R² < 0.5이면 외삽을 생략합니다. 3 데이터 포인트는 통계적으로 약한 근거이므로, 모든 외삽에는 한국어 경고 문구(caveat_ko)가 함께 표시됩니다.

4. 3단 검증 (aiindex validate)

  1. 스키마 — 모든 data/*.json이 JSON Schema를 통과.
  2. 참조 무결성 — Narrative의 related_metrics가 실제 Metric을 가리킴.
  3. 인용 무결성 — 모든 Quote가 원본 md에 verbatim으로 존재.

한 건이라도 실패하면 CI가 빌드를 차단합니다. 잘못된 숫자가 프로덕션에 가는 것보다 빨간 빌드가 훨씬 안전합니다.

5. 한계

  • 3 데이터 포인트 기반 외삽은 경향성 지표일 뿐 예측 모델이 아님. ARIMA/Prophet 같은 정식 시계열 모델은 의도적으로 배제했습니다 (과적합 위험 대비 가치 낮음).
  • 챕터별 narrate는 LLM 요약이므로, 독자는 중요 결정 전 반드시 우측 출처 블록의 원문 링크를 확인해야 합니다.
  • 지도·Sankey 등 일부 시각화는 Phase 3 이후에야 의미 있는 데이터 밀도를 가집니다.
